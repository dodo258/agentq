# 调度规则

本文列出 `tick` 怎样挑活、什么时候不启动、任务结束或出错后怎么处理。所有数字都是当前代码里的值，配置项见[配置参考](config.md)。

一次 `tick` 依次做这几件事：收尾已结束的任务，杀掉超时的任务，收门的结果，给排队的任务起门进程，挑活启动。agentq 自己不写业务代码。任务做到分支可合并，合并由引擎过门后做，见[质量门和引擎合并](features.md#质量门和引擎合并)；改 BACKLOG 的认领标记、提交和合并都由任务里的 `claude -p` 按 `agent-task` 技能完成。agentq 只在下文写明的情况下改 BACKLOG（去掉孤儿标记、标卡住、写修回归、写建议等），每次只提交这一个文件。

macOS 上 tick 由 launchd 每 5 分钟叫醒，Linux 上由 `systemd --user` 的 timer 每 5 分钟叫醒。下文的服务管理命令和日志在两个平台的对应关系见[文件参考](files.md#平台差异)。

## BACKLOG 语法

agentq 只读这几种固定写法，正文里顺带提到同样的词不算。

```markdown
## 待做

- [ ] 标题 —— 要什么；验收：可观察结果；范围：已知文件
- [ ] 标题 —— 内容（进行中：agent/1104-demo 2026-11-04 10:00）
- [ ] 标题 —— 内容（卡住：agent/1104-demo 两次没过）
- [ ] （低风险）标题 —— 内容

## 等用户决定

- [ ] 用哪种存储 （选项：A 用文件｜B 用 SQLite；推荐 A）
- [ ] 上线时间 （等条件：前面 7 条都合并）

## 建议

## 以后再说

## 已完成

- [x] 标题 —— 合并提交 abc1234；验收：去哪看
```

- 节标题按前缀匹配，要写中文。老项目的 `## 等……拍板` 写法同样当 `## 等用户决定` 识别。
- 同一节内 `## ` 之前的 HTML 注释不算条目。
- 条目标题是破折号之前、去掉进行中标记的部分。指纹是整行原文去掉进行中标记后的 SHA-1；改了条目文字就算新条目。
- 比较任务和条目时连项目一起比。两个项目里文字完全相同的条目互不影响。
- 提交号认 7 到 40 位小写十六进制。

## 默认分支

项目的默认分支由程序认，顺序是：主目录 HEAD 正在 `main` 或 `master` 上（包括还没有提交的）就用它；否则 `origin/HEAD` 指的分支（本地要有）；再看本地 `main`、`master`。下面说的 main 都指它，`<项目>-main` 锁只是名字。

HEAD 排在 `origin/HEAD` 前面，是因为 BACKLOG 从工作目录读，认领也提交到这里，用它才前后一致。

- 新任务起的时候认一次，记在任务上（`default_branch`），和提示词、认领、开分支是同一个值。默认分支不叫 main 时提示词里写明从哪开分支、合进哪里；叫 main 时提示词不变。
- 续跑、接手、退回重做沿用记下的。过门的基点、候选、合并、收尾、BACKLOG 和 PROGRESS 提交都走记下的，不再现认，切一下分支不会合错。升级前排队的老任务没记，才现认。
- 同一个项目可以同时有基于不同分支的任务，各走各的。「现在能不能接新任务」仍按上面的顺序现认，新任务记新结果。
- 接不了任务的两种情况：认不出默认分支（上面都没有，或者查不了 git），主目录不在默认分支上（在 feature 分支、游离 HEAD）。这时不起任务，不查登录和额度，不算连环失败，条目和续跑记录留着。tick 日志同样的原因只记一次，`agentq status` 一直写「不接任务」和要执行的命令，`agentq run` 也拒绝。切回去下次 tick 接着做。
- 已经在排队的门主目录不在记下的分支上：不合并，结论留着等你切回来，通知和 `agentq status` 写 `git switch <记下的分支>`。切到别的主线上也一样等着。
- 记下的分支没了：判不了，发决定卡片，不换分支合，放行也只合到记下的分支。写进 BACKLOG 的卡住原因不带本机路径。

## 挑活

- 项目：`projects_root` 下一层、`.git` 是目录的 Git 主目录，加上 [`extra_projects`](config.md#外面的项目) 登记的，按名字字母序。跳过以 `.` 开头的目录和 [`exclude_projects`](config.md#排除项目) 列出的项目。默认的 `~/projects` 不存在当作没有活，不写日志。
- 条目：`## 待做` 到下一个 `## ` 之间、行首是 `- [ ]` 的行。跳过 HTML 注释、含 `（进行中` 的行和标了卡住的行。
- 同一条目已有任务在跑就跳过。上次结束不到 `retry_after`（默认 12 小时）也跳过。撞用量上限的那次不算；上游瞬时错误按短退避，见[上游瞬时错误](#上游瞬时错误)。
- 写了依赖、还没做完的条目跳过，同项目下一条照挑，见下面的依赖和范围标记。
- 全局最多 `max_parallel` 个任务（待做和任务箱都算），同一项目最多 `per_project` 个（默认 2）。同项目已有任务在跑时，新条目要自己写了范围、在跑的每条也都写了范围、两两不重叠才起；没写范围的当会撞，一次一条。一次 tick 里同一项目可以连着起几条，直到 `per_project` 或全局上限。`agentq run` 守同样的规则。
- 各项目挑完还有名额，才接任务箱的一条。
- `agentq new` 启动后才出现的项目，tick 在它结束前不挑（第一条可能刚写进 BACKLOG 还没认领）。启动时就有的项目照常。

卡住标记只认两种写法：

- 括号标记：括号紧挨着「卡住」，后面接冒号、右括号或空白，在行里哪里都算。全角、半角、方括号、书名括号都认，比如 `（卡住：…）`、`(卡住)`、`【卡住】`、`[卡住 …]`。
- 行尾标记：去掉进行中标记、行尾空白和句末标点后，行以「卡住」结尾，且前面是行首、破折号或 `；，。|` 之一。

```text
算卡住：  … —— 卡住        …；卡住。
不算卡住：进程会卡住   标「卡住」   （卡住时 status 有提示）   [卡住检测](#卡住)   修 claude -p 卡住
```

**等条件标记**：「等用户决定」里的条目要等前置条件满足才轮到你定时，在条目第一行写 `（等条件：<条件>）`。带这个标记的条目巡逻不报，不推「要你定」，早报和「状态」的待决定项不算，只在早报详情列一行。只认括号紧挨「等条件」再接冒号的写法（全角、半角括号和冒号都行）。条件满足时由做完最后一条前置任务的 agent 去掉标记，去掉后 tick 把它当新条目推「要你定」。

**依赖和范围标记**：写在条目里哪里都行，只认括号紧挨「依赖」「范围」再接冒号的写法（全角、半角括号和冒号都行），正文顺带写的「依赖：」「范围：」不算。

- `（依赖：<另一条标题里的一段字>）`，可以写几个。「已完成」（和 `BACKLOG-archive.md`）里有标题含这段字的条目才算满足；还在别的节里没勾就等着；哪里都找不到也等，`agentq status` 在这个项目下写一句「依赖『…』找不到」，写错了改掉就行。
- `（范围：internal/gate/, docs/specs/）`，路径前缀，逗号或顿号分隔，`.` 表示整个仓库。两条范围里有一个是另一个的前缀（相等也算）就是重叠。只看路径前缀，不分析代码依赖；范围外也改了同一个文件的，后合并的那条在合并态上重新过门，冲突转给你。

```text
- [ ] 存储层 —— …（范围：internal/store/）
- [ ] 接口层 —— …（依赖：存储层）（范围：internal/api/）
- [ ] 文档 —— …（范围：docs/）
```

上面三条：存储层和文档可以同时跑，接口层等存储层合并后才起。

**低风险标记**：条目标题开头、标题结尾或行尾带全角的 `（低风险）` 时，任务用 `low_risk_model`（配了才生效），新开、续跑、接手都一样。正文中间、标题中间提到不算，半角括号不算。额度闸门仍按 `model` 算。`model_policy=auto` 时规则多一点，见[按任务类型选模型](config.md#按任务类型选模型)。

## 手动启动和自动接活的区别

| 限制 | tick 自动接活 | `agentq run` | `agentq new` |
| --- | --- | --- | --- |
| 暂停 `paused` | 遵守 | 不看 | 不看 |
| `retry_after` | 遵守 | 不看 | 不适用 |
| 连环失败熔断 | 遵守 | 不看，只提示一句 | 不看 |
| 并发上限 | 遵守 | 遵守 | 占 `max_parallel`，不算 `per_project` |
| 用量冷却、登录检查 | 遵守 | 遵守 | 遵守 |
| 额度到后台上限（会话默认 70%、周默认 90%） | 不启动 | 只提示 | 只提示 |
| 额度 ≥98% | 不启动 | 拒绝 | 拒绝 |

`agentq run` 不会挑标着进行中或卡住的条目。

## 任务结束立刻接下一条

每个任务都经一个外壳启动：`agentq _job <任务目录> <项目目录> <claude> <参数…>`（内部命令）。外壳在自己的进程组里启动 claude，等它结束后 exec 成 `agentq tick --after <任务id>`，马上收尾这个任务并挑下一条，所以排队的待做几秒内就接上。定时 tick 照旧保留作兜底（外壳被杀、tick 失败时由它收尾和接活）。

- `state.json` 记的 pid 仍是 claude 本身，claude 仍在自己的进程组里。`ps` 里多出的 `agentq _job …` 是外壳，任务结束后自己退出。
- 结束后的那次 tick 和定时 tick 共用 `tick.lock`，不会重叠。锁被占着时它最多等 60 秒（定时 tick 直接跳过）。
- 它同样遵守暂停、冷却、并发上限和 `retry_after`，日志写进 `~/.agentq/launchd.log`，开头是 `tick（任务 <id> 结束后）：`。
- 被 `agentq stop` 停掉或超时杀掉的任务也一样：下一条待做立刻启动，被停的那条受 `retry_after` 限制，stop 的回复和 `agentq status` 写明到几点才再接、现在就做用哪条 `agentq run`。想停住不接新活，先 `agentq pause`。
- `retry_after` 配得很短、又遇上 claude 一启动就失败时，会以秒级反复拉起。
- `"tick_after_job": false` 可以关掉，之后结束的任务只靠定时 tick。

## 启动窗口

起进程之前先写 `meta.json` 和 `~/.agentq/starting/<任务id>`，写不下就不起。外壳再写 `claude.pid`。tick 在这个窗口里被杀时，下一次 tick 按这些记录把任务接回来，不会再起一个；限定时间（30 秒）内仍没有 pid 就记启动中断。

外壳起了 claude 却没报回 pid 就死了时，记失败之前先按任务找进程：环境里有 `AGENTQ_JOB=<任务id>`，或命令行同时有 `--name` 标记和这个任务的会话 id。还在就接回来，占着名额照常收尾，不会出现第二个 claude；确认不在才记失败；`ps` 失败查不了就当它还在，不收尾，下次 tick 再查。过了 30 秒还活着的外壳杀掉，没有 claude 只剩子进程的清掉。

启动后写 `state.json` 失败时，状态里没有这个任务，以后的 tick 不会收尾它、超时也不会杀它，所以马上对它的进程组发 SIGTERM（10 秒后还在就 SIGKILL），任务记失败，摘要写「启动后写状态文件失败，已杀掉刚启动的 claude…」，并进当天汇总。

启动时用 `--session-id <随机 UUID>` 预先指定会话 id（续跑用 `-r` 沿用原 id），带 `--disallowed-tools Monitor`，这个参数对任务开的子代理同样生效。后台命令（Bash 的 `run_in_background`）没有禁，由 `agent-task` 技能的「一切等待前台等完」约束，漏网的由下面的中断核验接住。

## 用量上限

撞上才知道的那一种。

- 结构化字段优先：`api_error_status` 为 429 就是撞上限，不看文字。`subtype` 为 `error_max_*`（自己设的回合、预算上限）不算。
- 其余只在可能撞了上限的结果里找字样：`is_error` 为真、`api_error_status` 有值，或回合数不超过 3 且不是后台通知回合（`result_index` 为 0）。`result.json` 读不出时扫 stderr。正常做了很多回合的任务，结果里提到 rate limit 不算。
- 字样：`usage limit`、`rate limit`、`limit reached`、`hit your … limit`、`Request rejected (429)`、`API Error: 429`。
- 主动感知和闲时找活的结果里可能有外部文字，这两种任务只认结构化字段的 429。
- 能解析出重置时间（`resets 3:45pm`、`resets Mon 12:00am`、`resets Oct 12, 9am`、带时区括号的 `resets 8pm (Africa/Cairo)`，或 `usage limit reached|<unix 秒>`）就冷却到重置后 1 分钟。解析以 claude 退出的时刻为参照，收尾晚了也不会推到下一天或下一周。解析不出、不在 8 天之内或重置时刻已过，就冷却 `limit_cooldown`（默认 1 小时）。
- 冷却期间 tick 不启动，`run` 也拒绝。
- 撞上限的那次不算试过，冷却过后可以再挑。做到一半撞上的（BACKLOG 里这一条已标进行中）记为中断，冷却过后用同一会话续跑；同一条最多接连续跑 3 次，再撞就等你处理。

## 订阅额度

提前看，快用完就不领新活。

- 领活前读一次（tick 挑到能做的条目或要续跑、`agentq run`、`agentq night` 和 `review` 真要启动时）：`claude -p /usage --output-format json --tools "" --strict-mcp-config --setting-sources "" --no-session-persistence`，在空的临时目录里跑，环境变量同任务白名单。这是 Claude Code 的本地命令，不问模型，不花 token。
- 解析 `Current session: 9% used · resets Oct 11 at 11:29am (America/New_York)`、`Current week (all models): 17% used · resets …`、`Current week (Fable): 3% used · resets …` 这样的行。
- 读数存进 `state.json`，缓存 10 分钟。读完之后有窗口过了重置时刻，不到 10 分钟也重读。
- 计入的窗口：会话、本周（all models），以及只限某个模型、而任务用的正是这个模型的周窗口（模型名里含括号里的模型名）。tick 挑活时按主模型 `model` 查；按活换了模型的任务（低风险条目、复盘、巡逻分析、答问、找活……）启动那一刻再按它实际用的模型查只限模型的窗口，到后台上限就不启动（你亲手发起的到 98% 才拒绝），这一查只用缓存的读数。`agentq status` 的额度行写明只限某模型的窗口挡哪些任务（「只限 Sonnet：用 sonnet 的任务后台上限 90%，现在不启动」），哪个任务都不用的标「不计入」。

| 任一计入窗口 | 行为 |
| --- | --- |
| 到后台上限（`usage_stop_session_pct` 默认 70，`usage_stop_week_pct` 默认 90） | tick 不再启动新任务（包括续跑），正在跑的不动。会话窗口留出的那部分给你自己的会话用。定点叫醒的夜班、复盘也不启动，汇总记「夜班没有启动：订阅额度到了后台上限…」。`agentq run` 和手动 `night`、`review` 仍可用，只提示一句 |
| ≥98% | `agentq run` 和手动夜班、复盘也拒绝 |

- 到重置时刻再过 1 分钟，那个窗口就算恢复，同时重读一次。没读出重置时间的窗口要等下次读。
- 读不出（命令失败、超时 60 秒、报错、没有 `Current … % used` 行）当未知，照常跑。tick 日志记「额度未知，照常启动：…」，`agentq status` 的额度行标「未知（原因），照常接活」。闲时找活相反，读不出就不生成。
- `agentq status` 的额度行显示各窗口用量、重置时间和后台上限。挡住时调度行写明原因和恢复时间。state 里的读数过期时 status 现读一次，只显示，不写回。
- 当天汇总：每天第一次读到或档位（正常、到后台上限、≥98%、未知）变了，记一行「额度：…」，恢复时带「已恢复，照常接活」。

## 上游瞬时错误

- `api_error_status` 是 5xx 或 422（中转站常用 422 转上游过载），而且这次进程几乎没花钱（费用不到 $0.10，没有费用字段时回合数不超过 3）：记 `transient`，不计连环失败，也不清零。
- 待做条目按 15 分钟、1 小时各重试一次，不比 `retry_after` 长。用完之后那次照普通失败记，计连环失败、等 `retry_after`，所以上游长时间故障时熔断还能起作用。回到 `retry_after` 失败一次后又算新一轮，一个条目一天最多约 6 次。
- 408、409、401、403 和花了钱才出错的走普通失败。429 走用量上限。
- 条目已标进行中（比如续跑时出错）挑不到，不重试，等孤儿标记处理接手。夜班、复盘、对话没有条目可重试，只是不计连环失败。
- 这样的任务巡逻不报（夜班、复盘、对话照报）。

## 连环失败熔断

系统性故障（claude 一启动就报错、登录态坏了、某个全局配置有问题）会让每个任务秒退，任务结束马上 tick 又会拉起下一条。

- 秒退：没做完（失败、中断、启动失败）且运行不到 `breaker_quick`（默认 3 分钟）。运行时长算到 claude 实际退出（`result.json` 非空时取它的修改时间，没有就用收尾时间）。瞬时错误、被 `agentq stop` 停掉的、撞用量上限的、撞预算的、自动停的都不算，也不清零。
- 连续 `breaker_streak`（默认 3）个任务秒退就熔断：`breaker_cooldown`（默认 30 分钟）内 tick 不启动任何任务（包括续跑），当天汇总写一行「熔断：…」，带最近一个任务的 id 和摘要，`agentq status` 显示「连环失败熔断中」。
- 到期后只要还没有任务正常结束过，第一个任务再秒退就直接再熔断，时长翻倍，最多 `breaker_max`（默认 4 小时）。
- 有任务跑完，或跑了超过 `breaker_quick` 才结束（包括超时），计数和翻倍都清零。跑完的还会解除正在生效的熔断，汇总记「熔断解除：…」。熔断期间才结束的秒退不再计数。
- `agentq run` 不受熔断限制，结果照样计数。修好问题后想马上恢复，`agentq run` 试跑一条，跑完熔断就解除。
- 定点任务、`agentq new` 秒退同样计入连环失败，但跑完不清零、不解除熔断。

## 中断与自动续跑

claude 正常退出（`is_error` 为假）不一定是做完了：任务用后台命令等通知时，`claude -p` 会中途退出。所以收尾时还要核验：

- 条目标着进行中、标记写的分支上有合格的 `.agentq/ready.json`：做完了，排进门队列，下面几条不看。

- 重读该项目 BACKLOG：同一条仍在「待做」且标进行中，记为中断（`interrupted`）。从标记里取分支名，用 git 看它比默认分支多几个提交、有没有合并，写进摘要。结果来自后台通知回合（`origin.kind` 为 `task-notification` 或 `result_index` 大于 0）也写上。
- 条目已不在进行中，但结果里没写合并情况：也记中断，但不续跑，等你核对。
- 中断且有会话 id 的，下一次能启动任务时（遵守暂停、冷却、并发上限和登录检查，先于挑新条目；你用 `agentq run` 或 Telegram「做」亲手启动的条目暂停时也续跑）用同一会话续跑一次：`claude -r <会话id> -p "<续跑提示>"`，其余参数不变，记成一个新任务。提示写明后台的活已经不在了、从 git 和分支现状接着做。续跑前再看一眼 BACKLOG，条目已不在进行中就不续跑。
- 续跑的任务再中断就不再续跑，汇总写明续跑后仍中断，等你处理。
- 撞用量上限的任务不做上面的核验，但这一条仍标进行中时同样记中断，冷却过后续跑。
- 汇总里中断的任务记一行「中断：…」，续跑启动时记「续跑中：…」，续跑结束再记一行结果。

**报告做完但条目还在待做**：任务报告做完了，条目却还在「待做」且没标进行中或卡住时，第一次只记下，`retry_after` 后会再做一次。连续第二次（撞上限的那次不算）就标卡住并通知，不再自动重做。标记按指纹找条目，对不上才按标题。

**摘要怎么取**：结果里最后一个写着合并提交号的段落（只认「合并提交」「提交号」「merge commit」后面紧跟 7 位以上小写十六进制号）；没有就取最后一个说到合并情况的段落；再没有就取最后一段。正常跑完的任务，BACKLOG「已完成」里同标题的条目写了「合并提交 <号>」时，把它放在摘要开头（摘要前 80 个字已经有这个号就不重复；「待做」里还有同标题条目时不取，免得带出旧号）。条目标题被改过就对不上，只按结果文本取。

**门退回**：门没过时任务改记中断，用同一会话续跑，提示词带门的报告，最多 2 轮。在过门的条目不算孤儿，名额算全局的（门进程计入 `max_parallel`），不算项目的。

## 孤儿进行中标记

孤儿是指 BACKLOG 里标着进行中、没有运行中的任务、也没有待续跑记录的条目。不暂停时每次 tick 看一遍（不调模型）。只认行尾的标记，正文顺带提到的不算。状态文件刚重建的那次不看。巡逻已经写了「接手中断的…」待做的条目不重复处理。

- **24 小时内有活动就不动**：标记时间（没写时间就看 BACKLOG 的修改时间）、分支最后提交、worktree 文件修改时间（不算 `.git`、`node_modules`、`.build`、`DerivedData`）、这一条上个任务的结束时间。开着的交互会话靠这条保护；超过 24 小时没有任何提交和文件改动的会话会被当成没人在做。
- **手动停掉的不动**：这一条最近的任务是被停止的（`agentq stop`、Router 的 stop），标记还在时不接手、不去标记、不标卡住，`agentq status` 和「状态」各列一行，日志和汇总只记一次。去掉标记（之后 tick 按 `retry_after` 挑，或 `agentq run`），或回复那个任务的消息续跑，就恢复正常。标记还在时 `agentq run` 不会挑这一条。
- **标记里没写分支**：去掉标记并只提交 BACKLOG，下次当普通条目（同一次 tick 就可能挑到）。
- **写了分支，但分支没有默认分支之外的提交或已不在，worktree 干净**：多半是活已合并、只是 BACKLOG 没更新，也可能没动手，代码分不清。同样去掉标记，记日志、汇总并通知，不自动勾完成，等 `retry_after` 才再挑（`state.json` 的 `item_hold`，`agentq run` 不受影响）。通知写明多久后重新做，已经做完就移到「已完成」。
- **分支有未合并提交，或 worktree 有未提交改动**：启动接手任务，prompt 写明分支、worktree、从现状接着做。占名额，受用量冷却、额度、熔断、登录限制，先于挑新条目。未提交改动优先于「已合并」的判断。
- **同一指纹只接手 1 次**（启动失败、上游瞬时错误不算用掉）。没做完不走普通续跑；撞用量上限和机器重启照常续跑。结束后还标进行中就换成 `（卡住：接手后仍未完成，分支 …）`，提交并推「要你知道」，分支和 worktree 留着。接手任务结束后标记又写过或有人在分支上动，24 小时内不标卡住，也不再接手。
- 查不了 git（不是真仓库、认不出默认分支）只记日志，不动。主目录不在默认分支、BACKLOG 有没提交的改动时改不了，记日志，下次 tick 再来。

**打开调度后的第一次 tick 会处理所有超过 24 小时的旧标记**，有未合并内容的会各起一个接手任务，受 `max_parallel` 限制并产生费用。不想接手的先手动处理这些标记。

## 卡死早发现

- 每次 tick 看会话记录 `~/.claude/projects/*/<会话id>.jsonl` 和子代理记录 `<会话id>/subagents/*.jsonl` 的最新修改时间（都没有或比启动早就从启动时算）。超过 `stall_after`（默认 45 分钟）没增长：日志和汇总记一行「疑似卡死：任务 …」（同一次卡住只记一次，记录又长起来后解除），`agentq status` 在那个任务后面标「疑似卡死」。
- 看进展（纯代码，不调模型）：运行满 30 分钟的待做任务（夜班、复盘、巡逻分析、对话不看），每次 tick 解析主会话和子代理记录。

| 信号 | 条件 | 处理 |
| --- | --- | --- |
| 子代理失控 | 子代理日志 ≥25 个，或再派子代理的日志 ≥8 个 | `progress_autostop` 开着时自动停，见[失控兜底](#失控兜底) |
| 无改动 | 主会话和子代理合计 ≥90 分钟没有 Edit、Write、`git commit` | 只报 |
| 原地重复 | 主会话同一条 Bash 命令（压缩空白后）≥6 次，中间没有 Edit、Write | 只报 |
| 主会话空等 | 主会话 ≥45 分钟没有工具调用，子代理却还在动（子代理也停了归疑似卡死） | 只报 |

- 命中写日志、汇总、推送队列和 `agentq status`，同一信号不重报。
- 会话记录是 Claude Code 的内部格式：读不了、认不出、单文件超过 50MB 当未知，记一条日志，不报信号。
- 除了子代理失控都不自动杀：前台跑很久的测试、构建也会让记录一阵子不长。真卡住的由 `timeout` 杀，确认卡住也可以 `agentq stop <任务id>`。
- 没有预先指定会话 id 的旧任务不检查。

## 失控兜底

只防失控：额度留足，撞到后保留全部成果，能接着做。都不计连环失败，巡逻不重复报，也不为它起分析。

**预算**（`--max-budget-usd`，0 表示不传）：

| 任务 | 配置项 | 默认（美元） |
| --- | --- | --- |
| 待做、`agentq new`、任务箱 | `job_budget_usd` | 150 |
| 夜班 | `night_budget_usd` | 10 |
| 复盘 | `review_budget_usd` | 15 |
| 巡逻分析 | `patrol_budget_usd` | 2 |
| 闲时找活 | `suggest_budget_usd` | 1 |
| 主动感知判断 | `sense_budget_usd` | 1 |
| 发版准备 | `release_budget_usd` | 30 |
| Router、只读追问 | 固定 | 1 |
| 对话、小任务 | 不设 | - |

预算按单次运行算，`claude -r` 续跑不累计之前的花费。撞到时 `subtype=error_max_budget_usd`、`is_error=true`、退出码 1。

- 待做任务撞到：记中断，分支和会话留着，通知你，同一会话自动续跑一次（有一整份预算，提示词说明是撞了兜底、尽快收口）。续跑再撞才写 `（卡住：续跑后又撞预算上限 …，任务 <id>，分支 <名字>）`。判断第二次沿续跑链看有没有撞过预算，第一次是等通知中断续跑、这次才撞预算的还能接着做一次。条目不在进行中（还没认领）时不续跑，等 `retry_after`。
- `agentq new` 撞到：同样接着做一次，再撞不再自动做。接着做之前 tick 不抢它建的项目。
- 任务箱撞到：见[任务箱](features.md#任务箱)。
- 夜班、复盘、巡逻分析撞到：记中断，写汇总、推一条（巡逻分析只写汇总），不接着做。下次到点照跑，不会被当成没事跳过。

**子代理失控**：停掉进程组，分支和 worktree 留着，写 `（卡住：子代理失控，子代理 N 个，其中 M 个再派子代理，任务 <id>，分支 <名字>）` 并提交，通知你。

- 状态是「中断」，不是「已停止」。
- 主目录提交不了（不在默认分支、BACKLOG 有改动）时任务照样停，标记每次 tick 再写，这期间这一条不接手、不重挑。暂停时也写。
- 进程已经结束的不杀，下次 tick 按结果收尾。
- 任务箱任务标卡住写在 `inbox.md`。`agentq new` 没有条目可标，多出的目录和手动停掉时一样不自动做，`agentq run <项目>` 接着做。

**放下之后怎么接着做**（自动停、撞两次预算）。通知写明分支和 worktree 路径，有两种接法：

- **回复那条通知**：写模式接回原会话和原分支（`claude -r`），卡住标记换回进行中并提交。受名额和额度限制，不看暂停。预算按单次算，所以又有一整份。失控信号只算这次启动之后的子代理日志，不会一接回就又被停。BACKLOG 提交不了时不接回，回原因。只认 agentq 写的固定标记，且标记里的任务记录要对得上；你自己写的卡住，回复走只读追问。
- **去掉整个卡住标记**：不等 `retry_after`，下次 tick 或 `agentq run` 挑到这一条时，按任务记录（指纹或标题）找到记下的分支和 worktree，起一个新会话，提示词写明分支、worktree、从现状接着做。分支已经不在就当普通条目。这个新任务写进行中标记之前就失败时（上游 5xx、秒退），下一次还接这个分支；认领之后由它自己的标记管。

## 重启后不误杀

`state.json` 里记的 pid 和进程组号只在这次开机内有效。

- 每个任务启动时记下开机时间（macOS 读 `kern.boottime`，Linux 读 `/proc/stat` 的 `btime`）。收尾时和现在相差超过 60 秒且进程已不在，就是机器重启过：不碰进程组。claude 重启前已写好结果的照常按结果收尾，否则记中断，摘要写「机器重启过…」。这一条仍标进行中、有会话 id、本身不是续跑的，用同一会话自动续跑一次。重启造成的中断不算连环失败。
- 开机时间变了但进程还在，按校时处理，更新记录，照常看着。读不出开机时间时不判断重启，但清进程组仍要核对下面的标记。
- claude 退出后它拉起的子进程还在同一进程组里时，外壳等到 claude 退出就对进程组发 SIGTERM，5 秒后仍在就 SIGKILL，日志在 `launchd.log`。
- tick 收尾时组里还有进程（外壳没了、离退出可能已经很久），只有组里有进程带着这个任务的标记才发信号：环境里有 `AGENTQ_JOB=<任务id>`（macOS 用 `ps -E` 看，Linux 读 `/proc/<pid>/environ`）。没有标记就只记一行日志不杀。macOS 的系统自带命令（`/bin/zsh`、`/bin/sleep` 等）`ps` 看不到环境变量，组里只剩它们时认不出，不杀。

## 时钟跳变

时钟跳到未来又跳回来后，tick 读完状态先把不可能正常出现的值改回现在算：冷却超过 8 天（或 `limit_cooldown`，取大）加 1 小时、熔断超过 `breaker_max` 加 1 小时、条目等待超过 `retry_after` 加 1 小时、任务时间比现在晚 1 小时以上。改过会记日志。

## 状态文件损坏

- `~/.agentq/state.json` 内容坏了（JSON 不完整、有空记录、写成 `null` 或 `{}` 这种没有 `jobs` 键的内容）时，tick 先把它备份成 `state.json.bad-<年月日-时分秒>`，再按 `~/.agentq/jobs/*/meta.json` 重建任务列表。运行中的任务照常收尾、按启动时间做超时。日志和汇总记一行「状态文件损坏：…已备份为 …，按 N 个任务的 meta.json 重建…」，读不出的 meta.json 跳过并列出。重建那次 tick 只收尾不启动新任务，下一次照常接活。
- 重建丢掉的：连环失败熔断的截止时间和计数；用量冷却只能按撞上限任务的结束时间加 `limit_cooldown` 估回来（按提示的重置时间冷却的会变短）；`item_hold`；夜班和复盘的现状记录（下次照跑）。
- 读不了（没权限、I/O 错误、变成目录）当未知：不收尾、不启动、不备份，只记日志，修好才恢复。`agentq run`、`stop` 遇到坏文件也只报错，等 tick 重建。
- `config.json` 写坏时同样不覆盖，等你修。
- 同时写坏 `state.json` 和 `meta.json` 时认不出运行中的任务。

## 其他健壮性规则

- 外部命令（`git`、`gh`、`claude auth status`、`/usage`）都有超时，超时杀整个进程组，它们留下的子进程也会被清掉。
- `pause`、`resume` 和 Telegram 的「暂停」「恢复」只替换 `config.json` 最外层 `paused` 的值，别的字节不动，原子写回，权限不变，用 `config.json.lock` 串行。文件不是合法 JSON 对象时不写，报错。改名前再 stat 一次，文件变了就重来；stat 和改名之间落下的手改仍可能被盖掉（窗口几十微秒）。
- agentq 改 BACKLOG 前占 `<项目>-main` 锁（`~/.claude/state/locks/`，和 `with-lock.sh` 同一约定，写接手待做时最多等 2 分钟）。锁目录里没有 pid 文件超过 1 分钟当旧锁清掉。
- BACKLOG 是软链接时写到它指向的文件，按真实路径提交，保留权限。指向仓库外的报错，不改。
- BACKLOG 有没提交的改动时 agentq 不自动提交，可能是你的改动。超过 1 小时巡逻会报出来。拒绝是当场返回的，别的项目不受影响。
- `tick.lock` 没有持有者超时：拿着锁的进程被 SIGSTOP 停住时，所有 tick 都会跳过，要手动处理。
- SIGKILL 落在写临时文件的瞬间会留下 `.xxx.tmp-*`，不影响功能，没有自动清理。

## 环境变量白名单

任务的 claude、任务外壳和 `claude auth status` 只拿到这些环境变量，其余一律不传：

- `PATH`、`HOME`、`USER`、`LOGNAME`、`LANG`、`LC_*`、`TMPDIR`、`SHELL`、`SSH_AUTH_SOCK`；
- `CLAUDE_CONFIG_DIR`、`CLAUDE_CODE_OAUTH_TOKEN`；
- 代理 `HTTP_PROXY`、`HTTPS_PROXY`、`NO_PROXY`、`ALL_PROXY` 及小写形式；
- agentq 自己的 `AGENTQ_*`（如 `AGENTQ_JOB`）。

所以 `ANTHROPIC_API_KEY`、`ANTHROPIC_BASE_URL` 等 `ANTHROPIC_*` 不会让任务改走 API 计费或别的账号，Claude 会话注入的 `CLAUDECODE`、`CLAUDE_CODE_*` 也不会让任务以为自己是子会话。任务要用别的变量（比如某个服务的令牌），在项目里自己配置。

服务（launchd、systemd）只声明 `HOME` 和 `PATH`，不继承安装 shell 的 token 或代理变量。
