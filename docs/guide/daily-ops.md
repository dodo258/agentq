# 日常使用

## 添加任务

在项目目录打开 `claude`，用自然语言说明要做什么，`dispatch` 技能写成条目并启动：

```text
派活：给导出流程加失败重试并补测试
```

说「夜里做」或「只加到待办」时，只写条目，不启动。

也可以用命令添加：

```sh
agentq add "给导出流程加失败重试并补测试" --project my-app
```

或者手写进 `docs/BACKLOG.md` 的「待做」并提交，语法见[调度规则](../reference/scheduling.md#backlog-语法)：

```markdown
- [ ] 导出重试 —— 失败时重试 3 次；验收：断网时能看到重试日志，测试通过
```

## 立刻启动一条

```sh
agentq run my-app 导出重试
```

不看暂停和 `retry_after`，仍遵守并发上限和用量冷却。

## 新建项目

```sh
agentq new "一个记录读书笔记的网页工具"
```

任务本身不提问，补充的假设写进方案。第一条待做做到分支可合并，通过质量门后合并，通过烟测后生成交付单。结果写进当天汇总并推送。

配了 Telegram 时，开工前先问一次大方向。要跳过询问时加 `--direction "方向"`。

## 查看模块健康度

```sh
agentq health 项目名
```

显示最近 30 天每个模块的改动和修复次数，标出再修一次就要重写的模块，还有两周返工率。

## 查看状态

```sh
agentq status
```

前几行的含义：

- **调度**：`正常`，或暂停、冷却、额度、熔断的原因和恢复时间。
- **额度**：各窗口用量。
- **运行中**：任务 id、项目、标题、运行时长。任务后面标「续跑中」或「疑似卡死」。
- **各项目「待做」**：条数，以及进行中和卡住的数量。
- **最近结束**：状态、摘要、用量。

## 查看任务结果

```sh
agentq logs 1104-12          # id 写前缀，至少 4 个字符
```

输出里有接着查看会话的命令：在项目目录运行 `claude -r <会话id>`。任务文件在 `~/.agentq/jobs/<任务id>/`。

## 当天记录

```sh
cat ~/.claude/nightly/$(date +%F)-agentq.md
```

每个结束的任务一行，末尾是当天用量和质量小结。

查看多日用量和质量：

```sh
agentq stats 30
```

## 停止和暂停

```sh
agentq stop 1104-12          # 停止一个任务
agentq pause                 # 不再启动新任务，运行中的任务不受影响
```

`agentq stop` 之后下一条待做会立刻启动，要全部停住时先运行 `agentq pause`。

被 `stop` 的条目还带着进行中标记时，agentq 不接手，也不重新选中。不要这条时，把条目删掉或移走。要继续时，去掉 `（进行中…）` 标记，或回复那个任务的 Telegram 提醒。

## 恢复

```sh
agentq resume
```

## 任务中断

下面这些情况由 agentq 自动处理：

| 情况 | 处理 |
| --- | --- |
| 进程退出但条目还标着进行中 | 用同一会话续跑一次 |
| 撞上用量上限 | 冷却到重置时间，再续跑 |
| 机器重启 | 用同一会话续跑一次 |
| 撞上预算 | 同一会话接着做一次，再撞才标卡住 |
| 上游 5xx、422 | 15 分钟、1 小时后各重试一次 |
| 标记留下超过 24 小时没有活动 | 有未合并内容时接手一次，没有时去掉标记 |

## 标了卡住的条目

查看标记写的原因和 `agentq logs`。分支和 worktree 都保留。

- agentq 写的标记（子代理失控、撞两次预算）：回复那条通知，以写模式接回原会话。也可以去掉整个标记，下次选中时启动新会话，从分支现状接着做，不等 `retry_after`。
- `agent-task` 写的标记（`（卡住：<分支> <卡在哪>）`）：解决问题后去掉标记，按 `retry_after` 重新选中。
- 接手后仍未完成的标记：和 `agent-task` 写的标记一样处理。

详见[失控兜底](../reference/scheduling.md#失控兜底)。

## 等你决定的条目

任务遇到必须由你决定的事，会放进 BACKLOG 的「等用户决定」。

- 配了 Telegram：回复「要你定」那条消息，或点按钮。
- 没配 Telegram：在 `claude` 会话里说明选哪个，`dispatch` 技能写回条目并移到「待做」顶部。也可以手动修改。

`agentq patrol` 列出等待决定的条目，也可以直接查看项目的 `docs/BACKLOG.md`。

条目要等别的事完成后才需要决定时，写 `（等条件：<条件>）`，条件满足之前不提醒。

## 早报

打开 `review_enabled` 后，复盘每天 06:30 写 `~/.claude/nightly/<日期>.md`。配了推送时，08:00 后推送一条摘要，要你决定的和出问题的放在最前。

没有新内容时，复盘不启动模型，只写一份一句话的占位报告，早报照常推送。

## 验收意见

查看成品后有意见时，写成新条目。写法固定，才计入返工统计：

```markdown
- [ ] 验收 导出重试 的意见 —— 重试间隔太短；修 abc1234 引入的问题
```

## 归档 BACKLOG

```sh
agentq backlog archive my-app --dry-run
agentq backlog archive my-app
```

把「已完成」的旧条目移到 `docs/BACKLOG-archive.md`，不自动提交。

## 升级

运行 `agentq update`，或重跑安装命令。配置和数据保留。有任务在运行时拒绝替换，等它结束后再升级。

```sh
agentq update
curl -fsSL https://github.com/dodo258/agentq/releases/latest/download/install.sh | sh
```

新版本有问题时运行 `agentq rollback --yes`。
