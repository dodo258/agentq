# 派活

收到当前 BACKLOG 待办明确执行合同的进程（通常带 `AGENTQ_JOB`）应使用 `agent-task` 亲自完成，不用本技能重新派发同一任务。

本技能只负责把需求写清并启动调度，不在当前会话等待开发完成。用户/项目层保存项目别名、权限和通知偏好；通用技能不写死个人项目、账号或渠道。

## 1. 识别项目

- 会话已位于 Git 项目目录时，使用该项目，不要求它在 projects_root 下。
- 会话目录不是 Git 仓库、又不是要派给别的项目：问一次要不要 `git init -b main`，默认是。用户同意后再执行；不同意就停，不替用户把普通目录变成仓库。
- 否则运行 `agentq projects` 列出所有项目（每行目录名和路径，包括 `projects_root` 下的和登记在 `extra_projects` 的；找不到 `agentq` 时用 `$HOME/.local/bin/agentq`），按目录名和各项目 `AGENTS.md` 的项目说明匹配。第三列写着 `exclude_projects` 的项目，用户没点名就不派。
- 无法唯一匹配时，只列候选并问一次；不要凭个人别名猜测。
- 项目不存在且需求是新建项目时，加载 `new-project`。

## 2. 写入 BACKLOG

1. 项目还没有 `docs/BACKLOG.md`，或不在 projects_root 下：第一条用 `agentq add "<条目正文，不带 - [ ]>"` 写，它会生成缺的文件、判断检查命令写 `.agentq/verify`、把项目登记到 `extra_projects`（在项目目录里运行）。找不到 `agentq` 时用 `$HOME/.local/bin/agentq`。已有等价任务文件则沿用，不并建一套。
2. 一项需求一条，写入「待做」（`agentq add` 超过 800 字时把细节写进文件，条目写路径）：

   ```text
   - [ ] 标题 —— 要什么；验收：可观察结果和验证方式；范围：已知页面/文件；理解成：……；不是：……
   ```

3. 条目依据方案的，写方案路径和节名，如「按 `docs/specs/<方案文件>.md`「页面结构」第 2 节」：审查门会读写了路径的方案，照方案做的设计不当问题提。
4. 条目保存产品目标、验收和授权范围；本次入口会话不直接实现、不等待后台等派活步骤不写成后台任务的禁止实现指令。
5. 用户一句话包含多个可独立验收目标时拆开；有顺序或前置条件时写清。能确定改动范围就在行尾写 `（范围：internal/gate/, docs/）`（路径前缀，逗号或顿号分隔），同项目范围互不重叠的条目才会并行，没写的一次一条；必须等另一条先合并的写 `（依赖：<那条标题里的一段字>）`，可写多个。只用这两种括号写法，正文里的「范围：」不算标记。
6. 验收后的意见写成 `验收 <原条目标题> 的意见`；修复近期已合并改动时记录对应提交号，供质量统计使用。
7. 用户回复「等用户决定」的条目时，把决定和原分支写回该条目，再移到「待做」顶部。
8. 只提交本次改动的 BACKLOG；不带入其他会话文件。

## 3. 大方向：问一次，细节不问

设计、界面方向、前后端选型这类没定的事，交给 agentq 之前在当前会话问用户一次。细节不问，开发交给模型。

- 最多一次、不超过 3 个问题，每个带默认答案；有界面的附 2 到 3 个方向描述让用户选。一条消息问完，不来回追问。
- 用户回「随便」或不回，就按默认。
- 把结果写在条目行尾：`（方向：用户定：纸墨风，Go 后端）`，或 `（方向：按默认：简洁，Go 后端）`，只用这个写法，括号里不再放全角括号。写了这个标记后台不会再问，任务合同和审查门都从条目看到。
- 用户没空答、又想让他后面在 Telegram 上定：条目标题结尾写 `（大方向）`，不写方向，不用 `agentq run`，由 tick 开工前问。
- 项目要从零新建时走 `agentq new --direction "<方向>" "<一句话>"`；用户说随便就写 `--direction "随便"`。配置 `discuss_enabled` 关着时不问。

## 4. 交给 agentq

- 用户说“夜里做”或“只加到待办”：写入后停止，留给定时调度。
- 其他派活请求：对每条执行 `agentq run <项目目录名> <标题关键词>`，只需等命令返回启动结果，不等开发任务完成。找不到 `agentq` 时用 `$HOME/.local/bin/agentq`：桌面会话不一定读到新的 PATH。
- 并发已满或额度冷却时，保留 BACKLOG 条目，由后续调度接手；不要绕过限制。自动调度暂停不会阻止显式的 `agentq run`；用户仅要加入待办时不调用 run。
- 进度通过 `agentq status` 和 `agentq logs <任务ID>` 查询；报告目录按本机 agentq 配置读取，不在技能里写死通知渠道。

## 5. 回答

每条一行说明：是否已启动、任务 ID（如有）、完成后按哪条验收、如何查询进度。不要宣称尚未完成的结果，也不要因为派活而扩大远程推送、发布或付费授权。

## 6. 学到的约束

写条目前跑 `agentq evolve constraints <项目目录名>`（找不到命令用 `$HOME/.local/bin/agentq`）。列出的是这个项目被门拦过、确认过的事；和这次需求相关的，写进条目的验收（例如「验收：… 且不再出现 测试门：…」），无关的不写。命令不存在或没有约束就照常写。
