# 派活

agentq 把一句话从头交接到尾：产品经理出方案、划模块，各模块同时做，合到一起跑测试，全面审计一次、修一次，合进主分支，配了 Telegram 就发消息告诉用户。你不等它，也不替它做。找不到命令用 `$HOME/.local/bin/agentq`。

| 用户说 | 你做 |
|---|---|
| 做一件事 | `agentq do -C <项目目录> -`，从标准输入给需求；一件事一条，互不相干的同时派 |
| 先记着 | 写进项目 `docs/BACKLOG.md`「## 待做」，一行 `- [ ] 标题 —— 要什么`，提交；必须等另一条的写 `（依赖：<那条标题里的字>）` |
| 看待办、做某条、全做 | `agentq todo -C <目录>`，后面加关键字做一条，加 `all` 全做（没互相等的同时开工，做完打勾、接着做被挡着的） |
| 做得怎样 | `agentq ls`；细的 `agentq log <编号>` 看交接单，用几句人话说 |
| 停、卡住了接着做 | `agentq stop <编号>`、`agentq retry <编号>` |
| 验收的意见 | 写成新的一条 `do`，带上原来那条做了什么、提交号、用户原话 |

- 需求写用户原话，补上分得清的上下文（哪个页面、截图里看到什么、之前定过什么），不改意思，不替产品经理定做法。用户给的参考链接、已有方案文件写上。
- 项目：用户点名的，没点名就是当前目录。不是 git 仓库先 `git init` 并做一次初始提交；新项目建在 `${AGENTQ_PROJECTS:-$HOME/projects}/<英文短名>`，`.gitignore` 里加 `.claude/`。认不出是哪个项目问一句。
- 分不清大小不用管，产品经理自己判断。付款、对外发布、删用户数据、要账号的，派之前先问用户。
- 用户没说做就不派，也不主动从待办里挑。
- 回答一行一条：派了什么、编号、怎么知道做好了（配了 Telegram 会发消息，没配就 `agentq ls`）。没做完的不说做完。
