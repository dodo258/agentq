# 删用户数据的代码（删目录、删分支、删工作树、覆盖文件）
- 判「能删」时认不出、查不了、命令报错都当「留着」；默认只报告，显式开关（如 `--apply`）才删。
- 可再生白名单（`build/`、`dist/`、`node_modules/`）按整条路径判：路径里某一级叫 build 不等于整条能删。白名单目录里的密钥和配置（`.env`、`*.pem`、`*.key`、凭据文件）照样留着。`git status --ignored` 只在整个目录都被忽略时才报目录，目录里有被跟踪的文件时逐个报文件，两种都要测。
- 删之前当场再判一次，只删和报告里一样的那一项；能恢复的先记下恢复办法（分支的提交号和 `git branch <名> <提交>`）。
- 用工具自带的保险：`git branch -d` 不用 `-D`，`git worktree remove` 不加 `--force`（有改动或未跟踪文件时它会拒绝），`git clean` 先 `-n` 看。
- 每条删除路径的测试至少有一例「该留的留着」：白名单目录里放 `.env`、未跟踪文件、指向外面的软链接、`..`、大小写不同的名字、判完到删之间文件被改了。
