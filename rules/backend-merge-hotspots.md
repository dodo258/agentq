# 别让每条分支都改同一行（并行合并的冲突热点）
- 测试不写死「现在有几项」：题数、注册表条目数、清单长度、命令个数。每加一项都得改这一行，两条并行的分支各加一项就在这里撞冲突，后合的那条退回重来。改成从数据源数出来再比（数目录、读清单），或只断言新加的那项在、旧的还在；要防「读错了源」就断言一个只会涨的下限。
- 只往后加的记录（CHANGELOG、DECISIONS、注册表、路由表）：新条目照文件约定的位置加，不顺手改别人的旧条目、不整段重排；能拆成一项一个文件的（changelog 片段、每题一个目录）就拆。
- 交付前合入最新默认分支，冲突里两边新加的都保留，再按合并后的代码重跑受影响的测试；别人刚加的项算进去后，数和顺序都要对。
