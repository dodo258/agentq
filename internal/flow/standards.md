选型（写进方案「技术选型」一节，每样一句为什么。已有项目沿用它现在的，项目文档写了的以项目为准）：
- 先用成熟的，不自己造：同类需求先找标准库、现有依赖、口碑好还在维护的库。新依赖看许可证、最近更新、没解决的大问题。一类需求只用一个库。
- 语言按活选，条件差不多时：后台服务、命令行、要单文件分发用 Go；极致性能、长期运行不能出错用 Rust；数据处理、AI 调用、抓取用 Python；网页用 TypeScript；iOS 和 Mac 用 Swift、SwiftUI；安卓用 Kotlin。
- 数据：一个人、一台机器用 SQLite（开 WAL）；多人同时写、要联网共享用 PostgreSQL；只有几个设置用一个 JSON 文件。没有量级证据不上 Redis、消息队列、微服务。表结构变化走能重复执行的迁移，改之前先备份。
- 网页：完整网站用 Next.js，单页工具用 Vite + React；样式 Tailwind，组件 shadcn/ui，图标 Lucide，动画 Motion，拖拽 dnd-kit，跨组件状态 Zustand，表单 React Hook Form + Zod。纯展示的一两页用静态 HTML 就够。先找现成组件库和真实的好作品，再自己画。
- 界面：先定设计语言（颜色、字体、间距、圆角，写成变量）再做页面；内容用真实的；不要紫蓝渐变、一排三张一样的卡片、到处圆角阴影这类模板脸。手机宽度、深色、空和出错的样子都要有。有现成设计规范技能（如 frontend-design）就加载。
- 对外接口、网络、数据库、子进程都设超时；外部输入在入口校验一次；密钥只从环境或系统钥匙串来，不进仓库。

模块化：
- 按“换掉它别的不用动”来划：每块一件事、一个目录、一个小接口。块之间只走接口，不碰别人内部。依赖只朝一个方向。
- 核心逻辑不依赖界面、数据库和网络，能单独测。会变的（数据源、模型、支付、平台）放在接口后面，加一种就是加一个文件。
- 不为以后可能的需要加抽象、配置项和开关。
